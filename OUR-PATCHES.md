# Our changes to libmspub

This branch is libmspub (MPL-2.0, `COPYING.MPL`) from https://git.libreoffice.org/libmspub at commit
`652b2be3e5d4c14479f85794d7bc4eb5499d5735` (2026-10-04), with our changes as one commit per patch on top. Every
changed spot is marked `pub-converter` in the source. These are the libmspub sources used by PubToPDF
(https://pubtopdf.app), published as the MPL asks.

PubToPDF's own code (the WebAssembly wrapper, the renderer and the app) is separate and not covered by these files.
File names in the notes below (tdf…, fdo…, zen-…, poi …) are public test files from the LibreOffice and Apache POI bug
trackers and Zenodo.

Everything new we emit is a librevenge property whose name starts with `pub:` (plus the standard
`style:tab-stops`).

| 05 | Bullets: the list sub-blocks were read from the container's `info.data` (always 0) instead of `listSubInfo.data`. | 06 | Tab stops: positions were parsed and dropped. Emit `style:tab-stops` (position in inches). | 07 | Pages: every page in the document page list is written, including blank pages and pages with only master content (upstream dropped pages without shapes of their own). | 11 | Paragraph styles: a paragraph without a style index inherits style 0 ("Normal") from the second `STSH`, as `getCharStyleProps` already does for characters. Upstream used no default, so Normal's line spacing and space before/after were lost. | MSPUBCollector.cpp | tdf121800-schopro: 22 paragraphs carry no blocks; Normal has `0x34` = 1.19 sp and `0x13` = 6 pt after. | 12 | (a) Border callouts, MS-ODRAW types 47-49: geometry added (the callout shapes 41-43 with the rectangle stroked). (c) Page-number fields: Quill `TOKN` chunks (chunk id = text block index) are read; a one-character token with 0x2200 = 0 and 0x2202 = -5 is a page-number field, written as `insertField text:page-number`. (c) **Reverse-engineered**: the TOKN format is a PLC of character ranges, entries `[u32 length incl. itself][(u16 key, i32 value)...]`. A "continued on page" field may use the same code **[guess]**. (d) 7 corpus files: the stub pages hold 0 x 0 in rectangles, ellipses and lines; Publisher's thumbnails show the text page as page 1. |
| 13 | (a) **Table borders and cell fills.** Publisher draws them as extra Escher shapes with no ClientData; their ClientAnchor is a Contents-style block list: `0x01` kind (1 horizontal segment, 2 vertical segment, absent = cell fill), `0x02` (type 0x68) the table's seqnum, `0x04`/`0x05` start row/column and `0x06`/`0x07` end row/column (grid lines), `0x03` the cell index (fills). Colour = the shape's fill colour, width = its `lineWidth`, visible = `fFilled`. Emitted as `pub:table-borders` on `table` and `fo:background-color` on `tableCell`. CELLS blocks `0x0a`-`0x0d` emitted as cell `fo:padding-*`. (b) WordArt warp: `adjustValue`..`adjust10Value` as `pub:wordart-adjust`, shape flips as `pub:flip-h/-v`. (c) Paragraph block `0x33` = 1: the `0x34` line spacing is exact points in 1/8 EMU without the unit bits (upstream dropped it). A character style without a text size takes it from its definition chain in the third `STSH` (base index + differences). (d) `fSysIndex` colours (top byte 0x10) with no colour function no longer come out black. (e) Wrap distances (MS-ODRAW `dxWrapDistLeft`..`dyWrapDistBottom`) on every shape style that sets them. | TableInfo.h, ShapeInfo.h, MSPUBCollector.*, MSPUBParser.*, ColorReference.cpp | (a) **Reverse-engineered, confident on the layout**: drawn over the table grid, the 35 segments of tdf84096 reproduce the pedigree tree of its Publisher PDF line for line, and bulletin's 33 segments give its two grids (1 pt and 0.5 pt, black). 898 segments and 427 fills in 17 corpus files (two are Bugzilla copies). Line centred on the grid line and dashing codes: **guess**. Margin order left, right, top, bottom: **guess** (ccuk's 576-EMU values are top/bottom by look). (b) Values raw; meaning per warp type is MS-ODRAW/Office's (not checked against renders). (c) ccuk body text (style with `0x33` = 1, `0x34` = 1320800) = 13 pt; the PDF's pitch is 12.96-13.08 pt. ccuk's pull quote: 12 pt in the PDF, 12 pt in the third STSH, no size in the second. (d) tdf95348-csgrn: `0x10000011` fill is white in Publisher's screenshot. Index < 0xF0 -> white is a **guess** from that one file. (e) Documented in MS-ODRAW. Wrap *type* not found. |
| 14 | Rectangles with ONE border line (the same line on all four sides): upstream `getFudgedCoordinates` moved only the top edge (it reads `lines[0]` as the top line, `lines[1..3]` as the other sides). Now a half-inside single line leaves the stroke rectangle as stored (the line is centred on the shape's edge) and the text area shrinks by half the line width on all four sides; outside/inside single lines are also applied to all four sides. | MSPUBCollector.cpp | zen-13904428-osp-*: the 20 pt master frame's top sat 0.14 in high on every page (LibreOffice has the same bug); with the patch it matches the Publisher PDFs (tier-1 ink F1 0.94 -> 0.99 on all three files). 47 corpus files change, mostly sub-point moves of thin box borders and text-box edges; no file's score dropped. | 15 | Line ends: upstream parsed MS-ODRAW `lineStartArrowhead`/`lineEndArrowhead` and their width/length into `m_beginArrow`/`m_endArrow` but never wrote them. | 16 | Flipped text boxes: libmspub folds flips into the transform and read the text rotation back from it, so a box flipped horizontally came out upside down (180), and one rotated 180 and flipped vertically too. Now the text rotation is the shape's own rotation, + 180 when flipped vertically, and `pub:flip-h`/`pub:flip-v` are written on the text object. | MSPUBCollector.cpp | 2 corpus files change, both now upright: senior-news' running header "Central Tree Senior News Page 5" (flipped horizontally, was upside down) and village news' "Newsletter deadline" heading (Escher rotation -180 + flipV, was upside down; review r2 fix 6). The rule is Office's (PowerPoint/Word: vertical flip turns text 180, horizontal flip does nothing) **[assumed for Publisher; both headings read upright only with it]**. Native = WASM JSON on all 101 files. |

Not done (yet): other field types (dates, mail merge), autofit flags, wrap type (distances: patch 13), the
bullet font, emitting real librevenge list levels, CELLS blocks 0x07/0x09/0x0e (0x09 looks like the height of the
cell's text **[guess]**).

Known upstream quirk left alone: `mapTableTextToCells` has an `assert` that fires on 2 corpus files
(tdf95894, zen-5006956). Release builds have asserts off and the code after it stays in bounds (checked with
ASan/UBSan).
